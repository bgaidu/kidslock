# 儿童锁屏 · 认字解锁

一款面向**电视（Android TV）与平板**的儿童锁屏应用。按设定的"亮屏时长"自动锁屏，
孩子必须答对指定数量的五年级水平汉字拼音才能解锁，家长可用 PIN 码随时快速解锁。

## 功能

- **开机自启**：设备开机后自动恢复计时（默认开启）
- **亮屏计时**：只按屏幕亮着的时间扣减额度，熄屏待机、关机都暂停，不冤枉
- **定时锁屏**：15/30/45/60/90/120 分钟六档可选（默认 30 分钟），到时自动锁屏
- **重启仍锁**：锁屏状态下关机重启，开机后立刻恢复锁屏
- **认字解锁**：连续答对 3/5/10 题汉字拼音才能解锁（默认 3 题），答错计数清零
- **家长PIN**：家长可用 4 位 PIN 快速解锁（默认 1234，建议修改），防暴力尝试
- **防绕过**：改系统时间、杀后台、强行停止都无法绕过计时（见下方"计时与防绕过"）

## 安装方法

### 电视（小米等 Android TV）

1. 如果之前安装过旧版，建议先卸载旧版
2. 将 `kidslock-release.apk` 复制到 U盘，插入电视 USB 口
3. 在电视上打开「高清播放器」或「文件管理」，点击 apk 安装
4. 安装前需在「设置 → 账号与安全」开启「允许安装未知来源应用」

### 平板（荣耀 / 华为等）

U盘或浏览器下载 apk 直接安装即可（应用同时声明了手机/平板启动器入口）。
安装后**必须**完成下面的权限设置，否则开机自启与防绕过会失效。

### adb 安装（电视/平板通用）

```bash
adb connect <设备IP>:5555
adb install kidslock-release.apk
```

## 安装后必做的权限设置

不同品牌的设置项名称略有差异，以下按荣耀/华为平板与小米电视归纳：

1. **允许自启动**：设置 → 应用 → 应用启动管理 → 本应用 → 手动管理，开启「允许自启动」+「允许后台活动」。不开则收不到开机广播，重启仍锁失效
2. **悬浮窗权限**：设置 → 应用 → 特殊访问权限 → 显示在其他应用上层 → 允许。这是锁屏防绕过的核心兜底，必须开启
3. **防杀后台**：多任务界面下拉应用卡片加锁，电池设置里对本应用关闭省电优化
4. **有权查看使用情况**（强烈建议）：设置 → 特殊访问权限 → 有权查看使用情况 → 允许。授予后"强行停止后继续使用"的时间也能在重启后补扣（见计时机制）；不授予则这段无法追账

## 使用流程

1. **打开应用**，进入设置页：选择观看时长、解锁题数、设置家长 PIN（建议第一时间改掉默认 1234）
2. **开始计时**：按「开始计时」，到时自动锁屏；也可按「立即锁定」马上锁
3. **认字解锁**：锁屏界面显示一个汉字和 4 个拼音选项，遥控器方向键选择、确认键提交（触屏直接点选）；答对继续，答错计数清零；连续答对设定题数后自动解锁
4. **家长解锁**：锁屏界面选「家长解锁」，输入 4 位 PIN；输错 5 次锁定 30 秒
5. 解锁后可再次开始计时；锁屏状态下打开应用图标会被直接带回锁屏界面

## 计时与防绕过机制

### 亮屏计时

「观看时长」按**屏幕亮着的时间**消耗：

- 计时循环基于 `SystemClock.elapsedRealtime()`（开机单调时钟），**与系统时间无关**，改时钟无法延时
- 仅在屏幕亮起（`PowerManager.isInteractive()`）时递减，熄屏即暂停——熄屏待机、关机都不计时。孩子熄屏得不到任何好处：时间本来就只能亮屏消耗
- 每 5 秒原子持久化一组数据：剩余毫秒 + uptime / elapsed / 墙钟三枚时间戳

### 对账（防杀后台 / 强行停止）

服务意外死亡时，下次启动按两种情况追账：

- **同一轮开机内**（elapsedRealtime 未回退）：扣 `uptimeMillis()` 差值。uptime 在深度睡眠（熄屏挂起）时停走，所以"服务被杀但屏幕亮着"的时间照样扣回，熄屏期间死亡几乎不扣
- **经历过重启**（elapsedRealtime 回退）：用系统使用情况统计（UsageStats）统计上次时间戳以来**所有应用的前台使用总时长**并补扣——覆盖"强行停止后继续使用再重启"的漏洞。需授予"有权查看使用情况"权限，未授予时跳过补扣

已知的小偏差均偏保守方向（只多计不少计）：熄屏放音乐、AOD 常显等 CPU 不睡眠的场合会略微多计。

### 锁屏防绕过

- 锁屏时启用 HOME launcher alias（activity-alias 动态启停），按 HOME 回到锁屏界面
- 全屏悬浮窗覆盖桌面，拦截遥控器/触摸操作；点击或 OK 键回到锁屏
- 守护服务每 800ms 检查锁屏是否在前台，不在则重新拉起（进程内静态引用判断，不依赖已受限的 `getRunningTasks`）
- 锁屏状态存 SharedPreferences，关机重启后由 BootReceiver 立刻恢复
- 返回键被锁屏界面屏蔽；锁屏期间打不开应用设置页

> 注意：部分厂商系统会弹"选择默认桌面"或在后台强杀服务，导致 HOME 劫持或守护失效。
> 此时悬浮窗覆盖 + 家长 PIN 是最后的防线，请确保悬浮窗权限已开启。

## 编译方法

```bash
# 需要 JDK 17 和 Android SDK
export JAVA_HOME=<JDK路径>
export ANDROID_HOME=<SDK路径>

# 方式一：构建 debug APK（自动使用 debug keystore 签名，可直接安装）
# 适合开发测试，但荣耀/华为等设备可能拒绝安装 debug 签名的 APK
gradle assembleDebug

# 方式二：构建 release APK（需要配置正式发布密钥库）
# 设置环境变量后，使用正式 keystore 签名，可在所有设备安装
export KEYSTORE_FILE=<你的.keystore路径>
export KEYSTORE_PASSWORD=<你的密码>
export KEY_ALIAS=<你的alias>         # 可选，默认 kidslock
export KEY_PASSWORD=<密钥密码>       # 可选，默认同 KEYSTORE_PASSWORD
gradle assembleRelease
```

> **签名说明**：
> - **不再**为 release 构建自动回退到 debug keystore，避免"未包含任何有效的证书"错误
> - 未配置 `KEYSTORE_FILE` 时，release 构建产出**未签名** APK（需手动用 `apksigner` 签名或配置密钥库）
> - debug 构建 (`assembleDebug`) 仍自动使用 debug keystore，适合开发测试
> - GitHub Actions 构建时，在 Secrets 中配置 `KEYSTORE_BASE64`、`KEYSTORE_PASSWORD`、`KEY_ALIAS` 即可自动签名
> - 已发布的 kidslock-release.apk 由原作者签名；本副本的改动需自行编译签名后安装

## 注意事项

- 安装后务必完成"安装后必做的权限设置"四项，尤其悬浮窗权限
- 小米电视的「安全中心」可能清理后台，需加入白名单
- 汉字题库约 140 个五年级水平汉字，随机出题，最近 10 题不重复
- 没有绝对不可破解的软件防护：孩子若是设备管理员账户，任何应用都可被卸载。请让孩子使用受限/标准账户

## 本副本修复记录（相对上游）

### Bug 修复

1. **解锁指令永不执行**（2026-09-30）：`ACTION_UNLOCK` 原来写在已废弃的 `Service.onStart()` 里（Android 2.0 起系统不再回调），`unlockAndStop()` 是死代码——之前解锁全靠 watchdog 轮询发现状态变化才停服务。已移到 `onStartCommand()` 处理，解锁后悬浮窗立即移除、服务立即停止。
2. **计时依赖墙钟，改系统时间可绕过**（2026-09-30）：原实现用 `System.currentTimeMillis()` 算到期时间，把时间往后调即可无限续时。现改为**亮屏计时**（详见上文"计时与防绕过"）：`elapsedRealtime` 单调递减 + 熄屏暂停 + uptime 差值对账 + 跨重启 UsageStats 补扣，改时间、杀后台、强停重启三条路全部堵死。
3. **前台判断失真**（2026-09-30）：`getRunningTasks` 自 Android 5.1 起只返回调用者自己的任务，"锁屏是否在前台"的判断一直不准，导致 watchdog 反复做无效的 `startActivity`。改为 `LockScreenActivity` 用同进程静态引用上报自己的存活/前台状态。
4. **PIN 明文存储**（2026-09-30）：SharedPreferences 里直接存明文 PIN。改为随机盐 + SHA-256 哈希存储；旧版明文在首次校验成功时自动升级为哈希（按"长度非 64 位"识别明文，兼容旧版可能设置过的非数字 PIN）。
5. **PIN 存储损坏可导致永久锁死**（2026-09-30）：`sha256Hex()` 原实现 `catch (Exception) { return ""; }`——一旦哈希异常，空串被当成"已设置的 PIN"写入，之后任何输入都校验失败，孩子只能恢复出厂。现改为 `NoSuchAlgorithmException` 显式抛出（SHA-256 在 Android 上不会失败，但异常不该变成静默锁死）；`verifyPin()` 增加格式判定分支，长度非 64 且非 4 位数字的值视为"存储已损坏"直接拒绝匹配；`isPinUsable()` 供设置页判断能否走"重新设置PIN"恢复。
6. **设置页"立即解锁"按钮无 PIN 校验**（2026-09-30）：`MainActivity` 的解锁按钮直接 `setLocked(false)`。`onCreate` 的重定向挡住了锁屏状态下的进入，但边界情况可绕过——MainActivity 已打开期间若计时到期（`LockService.triggerLock()` 把 `isLocked` 置真），此时按一次"立即解锁"即完成绕过。已删除该按钮（解锁只应发生在锁屏界面，走认字或 PIN 两条路径）。
7. **`StandardCharsets.UTF_8` 拼写错误导致编译失败**（2026-09-30）：`sha256Hex()` 里 `StandardCharsets.UTF-8`（连字符）被 Java 解析为 `UTF` 减 `8`，编译报"找不到符号"。Java 常量名用下划线：`UTF_8`。已在 commit `b05b06c` 修正。

### 小清理

- 设置 PIN 弹窗原来只校验长度为 4，现校验必须是 4 位数字（2026-09-30）
- 删除从未使用的 `QUERY_ALL_PACKAGES` 权限（利于应用商店审核）（2026-09-30）
- 删除空实现的 `onUserLeaveHint()`、全屏悬浮窗上无意义的 `FLAG_NOT_TOUCH_MODAL`、未使用的导入（2026-09-30）
- 界面措辞"电视"统一为"设备"，平板使用不再违和（2026-09-30）
- `CharacterBank` 干扰项兜底原为无限补 `"n/a"` 占位文本——占位不是任何字的读音，孩子可一眼识别并跳过，把 4 选 1 降成 3 选 1。现改为题库不足时抛出 `IllegalStateException`（题库 144 条 / 141 唯一拼音，远够 4 选 1，正常不触发；抛错好过静默降级）（2026-09-30）
- `MainActivity.onResume()` 先 `removeCallbacks` 再 `post`，避免快速切回时堆叠多个 `updateRunnable`（2026-09-30）
- PIN 校验中区分"密码错"与"系统错误"：旧版明文升级哈希失败时只记失败计数、不回写错误值，避免 SHA 异常被误计为一次密码错误而加速触发锁定（2026-09-30）
- 设置 PIN 弹窗改为检查写入结果并给出成功/失败提示（2026-09-30）
- `MainActivity` 删除已失效的"解锁"按钮后，同步清理 `strings.xml` 中未引用的 `btn_unlock`（2026-09-30）
